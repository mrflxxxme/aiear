# Передняя растяжка — escalation policy (ADR-011 D4)

Фронт-зеркало задней растяжки ([`tripwire.yaml`](./tripwire.yaml)). Под автономным runner'ом discuss/plan-шаг **не** собирает ответы фаундера на каждый форк. Агент **владеет** большинством форков — решает, записывает решение, идёт дальше. **Останавливается и эскалирует** только для узкого, явного класса.

Этот файл — контракт, который читает auto-discuss ([`/autonomy:discuss`](../commands/autonomy/discuss.md)).

## Что агент ВЛАДЕЕТ (решает + логирует, никогда не спрашивает)

Каждый **implementation** и **архитектурный** форк. Агент выбирает опцию, лучше всего удовлетворяющую рубрике оптимальности (см. [`judge-panel.md`](./judge-panel.md)), записывает и идёт:

- Data-model / схема / layout таблиц / индексы (*новая* таблица — сама *миграция* всё равно трипает заднюю растяжку на мёрже, но дизайн-решение — агента).
- Алгоритм / библиотека / фреймворк в рамках фикс-стека (стек — [`_meta/stack.md`](../../.planning/_meta/stack.md), ADR-001..010).
- Границы модулей, seam-размещение, port/adapter, нейминг.
- Тест-стратегия, coverage-таргеты, дизайн фикстур.
- Какой pipeline-шаблон, как декомпозировать фазу, retry/параллелизм.
- Рефакторы, внутренний API-shape (не публичный), таксономия ошибок.
- Kotlin/Compose-идиомы, структура ViewModel/UseCase, DI-граф.

**Логирование обязательно** (это заменяет надзор фаундера):
- **Архитектурное** решение (констрейнит будущие фазы / ставит прецедент) → новый **ADR** по house-template + `log_decision.py --kind arch --adr ADR-0NN`.
- **Всё остальное** → `log_decision.py --kind impl` → аппендит в [`DECISIONS-LOG.md`](../../.planning/_session-context/DECISIONS-LOG.md).

## Что агент ЭСКАЛИРУЕТ (стоп, пишет в RUN-QUEUE, notify, ждёт)

Только два класса. Если форк не один из них — агент НЕ спрашивает, а решает.

### 1. Продуктово-рыночное поведение

Решения, требующие знания фаундером ЦА/рынка РФ, которого у агента структурно нет:

- Что юзер **видит / переживает** (UX-флоу капчера, тексты для юзера, голосовые команды, какая фича в scope волны).
- **Цена / тарифы / квоты / экономика** (любой user-visible коммерческий термин; MVP-1 биллинг).
- **Scope-cut'ы**, меняющие что продукт *делает* для клиента (отложить user-facing способность).
- Позиционирование / мессадж / какой сегмент/интеграцию (Obsidian / Telegram / календарь / Notion) приоритизировать.

> Litmus: *«Стал бы компетентный senior-инженер без рыночного контекста всё ещё гадать?»* Если правильный ответ зависит от клиентов/рынка/бизнес-стратегии, а не от кода — эскалируй.

> **Уже-решённое ≠ продукт-форк.** User-facing контент, зафиксированный ADR / PRD / spec — реализуется как есть, не ре-эскалируется: исполнение утверждённого spec'а — инженерия, а не новое продукт-решение. Эскалируется не всё *видимое*, а всё *нерешённое-и-видимое* — net-new user-facing выбор, не покрытый ни ADR, ни PRD, ни spec. Копию/сценарии, которые агент должен *породить* (напр. онбординг наушников, демо-фразы капчера), веди по пути **автономный-драфт → founder review-гейт**, не up-front эскалацией.

### 2. Трипвайр-категории (тот же список, что задняя растяжка)

Миграции по существующим таблицам/RLS · auth/аккаунт/сессии · billing/деньги · секреты/ключи/STT-LLM-прокси · ПД/ФЗ-242-аудио-резидентность · **нативный фон/разрешения** · слом публичных app↔backend-контрактов. Эскалируют на **дизайн**-шаге тоже (не только на мёрже), потому что *подход* так же чувствителен, как диф.

> **Нативный фон — двойной гейт (D3-native).** Форк, трогающий mic-FGS/CDM/MediaSession/manifest, И эскалирует подход (если net-new/рискованный), И тянет обязательный `device_survival`-evidence-гейт. Спорный нативный подход под главным риском EARAI — эскалируй; рутинный (по утверждённому ADR-002-legal паттерну) — реализуй, но device-evidence обязателен.

## Процедура решения (auto-discuss гоняет per-форк)

1. **Перечисли** опции форка + рекомендованный дефолт (с обоснованием против рубрики).
2. **Классифицируй:** продукт/рынок? трипвайр-категория? → **ЭСКАЛИРУЙ**. Иначе → **agent-owned**.
3. **Owned + широкий форк** (архитектура/алгоритм/схема, опции материально расходятся) → [judge-панель](./judge-panel.md); бери победителя. **Owned + узкий** → рекомендованный дефолт.
4. **Логируй** (`arch`→ADR, иначе `impl`).
5. **Эскалированный** → аппенд escalation-record в `RUN-QUEUE.md`, `PushNotification` (+ Telegram), и **блокируй только этот форк** — продолжай независимую работу; ставь зависимый путь на паузу до `/ack`.

## Формат escalation-record (→ RUN-QUEUE.md)

```
### ESCALATION · <phase> · <UTC ts> · <product-market|tripwire:<category>>
- Fork: <одна строка>
- Options: A) … B) … [C) …]
- Agent's lean: <опция> — <почему, вкл. рубрику>
- Why escalated: <нужно рыночное знание | необратимая категория>
- Blocks: <какие downstream-таски ждут>
- Resolve: reply `/autonomy:ack <id> approved` или `revise <id> <note>`
```
