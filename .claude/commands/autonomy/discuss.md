# /autonomy:discuss — автономное обсуждение фазы (ADR-011 D4)

Гоняй front-autonomy рутину для фазы **$1**. Ты заменяешь интерактивный форк-грил автономным decide-and-log, эскалируя только там, где знание фаундером ЦА/рынка структурно необходимо.

## Контракты (грузи JIT)
- `.claude/autonomy/escalation-policy.md` — что владеешь vs эскалируешь.
- `.claude/autonomy/judge-panel.md` — как обрабатывать широкие форки.
- `.planning/agent-handbook/00-START-HERE.md` — bootstrap-маршрут.

## Шаги

1. **Bootstrap.** Прочитай spec фазы **$1** (`specs/<wave>/<$1>.md` с EARS) + `STATUS.md` + входящий хендоф. Заземляй каждое утверждение на код, не на память (grep, не предполагай).
2. **Перечисли форки.** Каждое реальное решение фазы: опции + рекомендованный дефолт с обоснованием против рубрики оптимальности.
3. **Классифицируй каждый форк** per `escalation-policy.md`:
   - **продукт/рынок** или **трипвайр-категория** → **ЭСКАЛИРУЙ**: драфтуй escalation-record (формат в политике). НЕ решай. Продолжай независимые форки.
   - **agent-owned** → решай.
   > Нативный фон (mic-FGS/CDM/MediaSession/manifest): net-new/рискованный подход → эскалируй; рутинный по ADR-002-legal паттерну → решай, но помни: фаза потянет обязательный `device_survival`-evidence-гейт (D3-native).
4. **Резолв owned-форков.**
   - **Широкий форк** (архитектура/алгоритм/схема, высокий blast-radius) → judge-панель: N подходов → рубрика `evaluator` → победитель + прививка.
   - **Узкий** → рекомендованный дефолт.
5. **Логируй каждое owned-решение** через `scripts/autonomy/log_decision.py` (`--kind arch --adr …` для архитектурных — пиши и ADR; `--kind impl` иначе). Передавай `--phase $1`.
6. **Emit план.** `PLAN-$1.md`: резолвнутые решения, декомпозиция тасков, флаги `wide_fork:`/`escalated:`, pipeline-шаблон. Если что-то эскалировано — перечисли, что **заблокировано до `/ack`**, а что может идти сейчас.

## Output
- Короткая сводка: N форков → X owned+logged, Y escalated (с escalation-records).
- Путь `PLAN-$1.md`.
- Если ничего не эскалировано — скажи: фаза готова исполняться автономно (до PR-гейта; мёрж — фаундер-ack под rails-first).

## Guardrails
- Никогда не решай продукт/рынок или трипвайр-форк сам, даже если дефолт очевиден — эскалируй.
- Уважай фикс-стек (ADR). Отклонение — само по себе архитектурное решение → ADR + log.
- Нативные баны ADR-002 (BOOT_COMPLETED mic-старт, AccessibilityService-автоматизация, silent-audio) — не форк, а запрет; предложение такого пути = ошибка, не решение.
