# ADR-014 — minSdk 31 и tiered-захват

## Контекст
Спайк S1 запинил `minSdk=34` (enforcement типа `FOREGROUND_SERVICE_MICROPHONE` в
Android 14), пометив продуктовый minSdk «отдельным решением позже». PRD строит
бизнес-кейс на массовом рынке РФ, где Android 14+ — меньшая часть парка: minSdk 34
режет заявленный рынок (противоречие C4 аудита 2026-07-07). Технически mic-FGS
работает и ниже (тип FGS-microphone существует с API 30; с 34 — жёсткая декларация
и enforcement while-in-use).

## Решение (ратифицировано фаундером, grill 2026-07-07 §1.2)
**Продуктовый `minSdk = 31`** (Android 12+) с **тирами возможностей**:

| Tier | Android | Возможности захвата |
|---|---|---|
| **Full** | 14+ (API 34+) | Полный фоновый захват: mic-FGS переживает screen-off ≥60 мин (S1), CDM-автозапуск (S2), tile/media-button (S3) |
| **Degraded** | 12–13 (API 31–33) | Захват при активном приложении / включённом экране; screen-off-выживание не гарантируется и не обещается в UI |

UI честно коммуницирует тир на онбординге (F4): пользователь на 12–13 видит, что
«ловля с погашенным экраном» требует Android 14+.

## Последствия
- `app/build.gradle.kts`: `minSdk 31` (правится в фазе F1, не в спайках — спайки
  Wave 0 остаются на 34, они доказывают Full-tier).
- Device-матрица Wave 0/F1 дополняется одним API 31–33-устройством (FTL) для
  Degraded-smoke; полный OEM-фокус остаётся на 14+.
- EARS-критерии F1/F4 разделяются по тирам: AC «screen-off ≥60 мин» действует
  только для Full-tier.
- Рост охвата рынка против minSdk 34; рост матрицы против minSdk 26 — осознанный баланс.

## Альтернативы (отклонены)
- **minSdk 34** — максимальная простота, но премиальная ниша вместо заявленного рынка.
- **minSdk 26–29** — три ветки поведения фона, матрица тестирования и OEM-риски дороже всего для автономных агентов.
