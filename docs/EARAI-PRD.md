## 1. Резюме для руководства

> **AIEAR** — Android-приложение (РФ, далее рус-СНГ), которое превращает любые Bluetooth-наушники в «ловца мыслей» для вашего второго мозга. Поймал идею на ходу голосом → ИИ распознал, структурировал и **зафиксировал в действие** (встроенный inbox-заметки, календарь, напоминание, Telegram, Obsidian) — телефон доставать не нужно. Дальше — захват встреч/лекций, а в перспективе — полноценный голосовой ИИ-ассистент поверх любого железа.

**Для кого (на старте):** русскоязычные продуктивные пользователи 20–40 лет — студенты/исследователи и tech-аудитория, живущие в Obsidian/Notion/Telegram, которым нужно ловить и систематизировать мысли на ходу.

**Бизнес-логика:** рынок ИИ-в-ушах сформирован «Яндекс Дропс» (8 990 ₽, старт 9 июня 2026, 15k+ заказов за неделю). AIEAR занимает **соседнюю незанятую нишу** — софтовый капчер/второй мозг поверх уже имеющихся наушников, без покупки железа. Монетизация с MVP-1: подписка ~399–699 ₽/мес + годовой тариф.

**Способ реализации:** соло-фаундер (тех-экспертиза) + ИИ-агенты по spec-driven процессу. Этот PRD — канонический вход в агентную сборку.

## 2. Контекст и проблема (актуализировано)

### 2.1. Рыночный триггер
«Яндекс Дропс» доказал спрос на «ИИ в ушах без доставания телефона» (РФ/KZ/BY/UZ). OpenAI «io/Sweetpea» — анонс ожидается во 2П2026, реальные продажи возможно 2027, **в РФ недоступен** → не near-term конкурент. Окно для софтового подхода открыто.

### 2.2. Боль пользователя
- **Мысль на ходу теряется** за 20–30 сек «остановиться → достать телефон → открыть заметки → надиктовать». Идея уходит.
- **Пойманная мысль без действия = потерянная мысль** — нужна не запись, а фиксация в систему (календарь/задачи/заметки).
- **Установленная база наушников** в РФ огромна; менять их ради функции — высокий порог.
- **Конспект встреч/лекций вручную** медленно и неудобно.

### 2.3. Стоимость бездействия
Дропс формирует привычку «ИИ-в-ушах» вокруг своего железа+экосистемы. Окно для software-first капчера — ориентировочно **6–12 мес** до насыщения. Но воюем не с Дропс, а занимаем соседнюю территорию (PKM/капчер), где железного конкурента нет.

## 3. Продуктовое видение (поэтапно)

> **Vision (долгосрок):** AIEAR — программный слой голосового ИИ поверх любых наушников. Мы не продаём железо — мы делаем умными те наушники, что уже в ушах.

Видение разворачивается **итерациями**, и нарратив каждой фазы совпадает с тем, что продукт реально умеет:
- **MVP-0 →** «второй мозг»: ловец мыслей с фиксацией в действие.
- **MVP-1 →** «личный ИИ-диктофон встреч и лекций» (денежный нарратив).
- **V1 →** «любой ИИ в любых наушниках» (hands-free ассистент, выбор модели, iOS) — здесь и встаём против Дропс/Алисы.
- **V2+ →** B2B/Enterprise, SDK для производителей наушников.

## 8. Функциональный скоуп по волнам (итерации)

> Каждая волна = одна user-facing способность с EARS-критериями приёмки. Детальное ТЗ на каждую волну составляется отдельно на основе этого PRD.

### Wave 0 — Спайки риска (5 «гейтов взлёта») 🔴 блокирующая
Цель: доказать выполнимость до продуктовой разработки. Агент пробует, фаундер валидирует на реальном устройстве.

- **S1. Фоновый mic-FGS переживает screen-off.**
  - **EARS:** WHEN запись запущена и экран гаснет, THE SYSTEM SHALL продолжать захват аудио без прерывания ≥ 60 мин на эталонном устройстве.
- **S2. Автозапуск по подключению наушников (CompanionDeviceManager).**
  - **EARS:** WHEN сопряжённые наушники подключаются по BT, THE SYSTEM SHALL легально стартовать сервис захвата из фона без открытия UI.
- **S3. Активация без рук (Quick Settings tile + media-button hook).**
  - **EARS:** WHEN пользователь тапает tile ИЛИ даёт двойное нажатие media-кнопки (когда AIEAR — активная медиа-сессия), THE SYSTEM SHALL начать сессию захвата < 1 сек.
- **S4. RuStore Pay SDK sandbox: подписка + рекуррент.**
  - **EARS:** WHEN тестовый пользователь оформляет подписку в sandbox, THE SYSTEM SHALL активировать платный статус и провести рекуррентное продление.
- **S5. STT-стриминг латентность.**
  - **EARS:** WHILE пользователь говорит, THE SYSTEM SHALL отдавать промежуточный транскрипт с задержкой < 2 сек на 4G.
- **S6. Русский on-device wake-word на взведённом сервисе** (оценочный, не блокирующий). Движок Picovoice Porcupine / Vosk, кастомное слово «Эй, бадди» (wake-word «Buddy»); сервис взводится через CDM при подключении наушников.
  - **EARS:** WHILE наушники подключены и сервис захвата взведён, THE SYSTEM SHALL детектировать wake-word «Эй, бадди» и стартовать сессию захвата без касания экрана.
  - **EARS:** WHILE wake-word-слушание активно, THE SYSTEM SHALL удерживать дополнительный расход батареи ≤ 3%/час (бюджет; VAD-гейт перед инференсом).
  - **EARS:** IF наушники отключены, THEN THE SYSTEM SHALL останавливать wake-word-слушание (не слушать 24/7).
  - **Результат спайка решает:** едет ли wake-word в MVP-0.x. Anytime-wake-word (приложение убито/без наушников) — вне скоупа, только V1 (путь A, default-ассистент).
- **Гейт:** **S1–S5** зелёные на ≥2 OEM (вкл. Xiaomi/Samsung) → переход к MVP-0. **S6** — оценочный: его исход определяет скоуп MVP-0.x, но не блокирует MVP-0.

### MVP-0 — «Поймай мысль» (free, доводим до блеска) 🟢 ядро
Цикл: **поймал голосом → ИИ распознал/структурировал → предложил действие → зафиксировал в destination.**

- **F1. Захват мысли.** Запуск (tile / BT-autostart / кнопка в приложении / media-hook / wake-word «Эй, бадди» — пока наушники подключены, если спайк S6 зелёный) → запись короткой реплики → стриминговый STT (Yandex SpeechKit). Каждая захваченная мысль **сначала персистится во встроенный inbox** (локальный шифрованный стор — inbox-first, ADR-015).
  - **EARS:** WHEN сессия захвата активна, THE SYSTEM SHALL транскрибировать речь и показать текст в течение 3 сек после окончания реплики.
  - **EARS:** WHEN реплика захвачена, THE SYSTEM SHALL персистировать мысль во встроенный inbox до и независимо от любой доставки в destination.
- **F2. ИИ-структурирование + классификация.** LLM (GigaChat-2 Lite — дефолт за сменным адаптером, ADR-013) определяет тип (задача/идея/напоминание/заметка), теги, заголовок. Пороги качества: классификация типа ≥85% на golden, WER STT <15%.
  - **EARS:** WHEN транскрипт готов, THE SYSTEM SHALL вернуть структурированный объект {заголовок, тип, теги, нормализованный текст} и предложить destination + CTA.
- **F3. Фиксация в действие (экспортёры из inbox, ADR-015).** Must-набор: **Share Sheet/Markdown-экспорт** (catch-all), **системный Календарь/Напоминания**, **Telegram** (отправка себе), **Notes — встроенный inbox приложения**. Should: **Obsidian** (SAF-запись .md в vault + `obsidian://new` URI fallback) — реализуется в F3, но не держит гейт волны. Destination'ы — асинхронные повторяемые экспорты из inbox (retry-очередь, идемпотентность по `thought_id`).
  - **EARS:** WHEN пользователь подтверждает предложенное действие, THE SYSTEM SHALL создать запись в выбранном destination и подтвердить голосом/уведомлением.
  - **EARS:** IF целевая интеграция недоступна, THEN THE SYSTEM SHALL пометить мысль в inbox как «не доставлено» и повторить экспорт при восстановлении доступности (мысль не теряется — она уже в inbox).
- **F4. Онбординг наушников.** Автоопределение гарнитуры, тест активации, сохранение маппинга, гайд по tile.
- **F5. История + поиск + sync.** История заметок с поиском поверх inbox-стора (сам стор создаётся в F1 — ADR-015); sync в RF-облако (Yandex Cloud, ADR-013).
- **F6. Офлайн-капчер (базовый):** on-device STT (Vosk/whisper.cpp) при отсутствии сети — запись и черновой транскрипт продолжаются.
  - **EARS:** WHILE сеть недоступна, THE SYSTEM SHALL захватывать и черново транскрибировать офлайн, синхронизируя при появлении сети.
- **F7. Голосовые команды в сессии.** Внутри активной сессии пользователь управляет функциями голосом: разметка («это важно»), выбор destination/CTA («в напоминания на завтра 9:00», «отправь в Obsidian»), «новая мысль», подтверждение/отмена — без касания экрана.
  - **EARS:** WHILE сессия захвата активна, THE SYSTEM SHALL распознавать голосовые команды управления (разметка, выбор destination, подтверждение/отмена) и выполнять их без касания экрана.
  - **EARS:** IF голосовая команда распознана с низкой уверенностью, THEN THE SYSTEM SHALL переспросить голосом перед выполнением необратимого действия.
- **Монетизация:** отсутствует (free, без карты). Мягкий лимит — задел под MVP-1.
- **Fast-follow (MVP-0.x):** Notion API, Google Calendar (OAuth), Todoist, Яндекс.Календарь.

### MVP-1 — «Лекция / встреча» (включение биллинга) 🟢 приоритет выручки
- **M1. Непрерывный захват** 30–90 мин (на базе S1/S2), стриминговый транскрипт с метками времени.
- **M2. Структурированный протокол:** разделы (тема, тезисы, задачи, вопросы, важное), экспорт PDF/Markdown/в Obsidian/Notion.
  - **EARS:** WHEN запись встречи завершена, THE SYSTEM SHALL сгенерировать структурированный конспект с тайм-кодами в течение 60 сек после остановки.
- **M3. Голосовая разметка по ходу:** «это важно» / «добавь к предыдущему» → метки приоритета.
- **M4. Согласие на запись:** экран явного согласия при старте, фрейминг «личный диктофон», опц. звуковой индикатор; ответственность на пользователе.
  - **EARS:** WHEN пользователь стартует запись встречи, THE SYSTEM SHALL показать экран согласия и не начинать запись до подтверждения.
- **M5. Биллинг (RuStore Pay SDK + свой эквайер):** Free / Standard / Pro, квоты, рекуррент по СБП, чеки 54-ФЗ.
  - **EARS:** WHEN пользователь исчерпал квоту транскрипции тарифа, THE SYSTEM SHALL предложить апгрейд/овередж и не списывать сверх лимита без подтверждения.

### V1 — Ассистент и расширение (vision реализуется)
- **V1.1. Hands-free ассистент (путь A):** роль `ROLE_ASSISTANT` + `VoiceInteractionService` как опциональный «Power Mode»; детект сброса роли при обновлении.
- **V1.2. Голосовой диалог + TTS** (Yandex/SaluteSpeech).
- **V1.3. Выбор ИИ, включая intl (Claude/GPT)** через KZ-юрлицо + backend-прокси, с явным согласием на зарубежную обработку.
- **V1.4. iOS-волна:** капчер через «Привет, Siri → App Intent» + Control/Lock-widget + Action Button/Watch; биллinг по [ios-billing-options](research/ios-billing-options.md) (Telegram-бот / web-reader); on-device STT через iOS 26 `SpeechAnalyzer`.
- **V1.5. Гео-расширение:** рус-Казахстан.

### V2+ — B2B / Enterprise
Корпоративные протоколы встреч (бот, объявляющий запись), SSO, аналитика, SLA, интеграции с CRM, SDK для производителей наушников. Конвертация ИП → ООО.

## 9. Non-Goals (вне скоупа на старте)
- Полноценная офлайн-LLM на устройстве (требует 4+ ГБ).
- Производство наушников/аксессуаров.
- Перевод в реальном времени.
- Голосовое управление чужими приложениями на Google Play (бан AccessibilityService) — рассматривается только RuStore-сборкой в V1+.
- iOS в первой волне (см. V1.4).
- Web/десктоп.

## 10. Технические требования и архитектура

### 10.1. Платформа и активация (по ресёрчу)
- **Android-first.** Активация MVP — путь B: **CompanionDeviceManager** (автозапуск по BT) + **Quick Settings tile** + кнопка в приложении + **media-button hook** (бонус). Фоновый захват — **mic-FGS** (`FOREGROUND_SERVICE_MICROPHONE`), стартуемый из foreground/через CDM-исключение.
- **minSdk 31 + тиры возможностей (ADR-014):** **Full** (Android 14+) — полный фоновый screen-off-захват (mic-FGS ≥60 мин, CDM-автозапуск, tile/media-button); **Degraded** (Android 12–13) — захват при активном приложении/включённом экране, screen-off-выживание не обещается в UI. Онбординг (F4) честно коммуницирует тир.
- **Голосовая активация (в рамках пути B):** голосовые команды внутри активной сессии (F7) — полностью доступны. Hands-free **wake-word** («Эй, бадди») — только на **взведённом сервисе пока наушники подключены** (CDM → mic-FGS → on-device hotword: Picovoice Porcupine / Vosk), валидируется спайком S6. Программный hotword работает лишь внутри уже работающего сервиса; **always-on hotword при убитом приложении / без наушников зарезервирован ОС за default-ассистентом** → только V1 (путь A).
- **Default-ассистент (`ROLE_ASSISTANT`)** — только V1 «Power Mode», не MVP.
- **Запрещено:** `BOOT_COMPLETED` mic-старт; AccessibilityService-автоматизация на Play; silent-audio Now Playing (для iOS-волны).
- Детали и OEM-оговорки: [tech-scenarios-findings](research/tech-scenarios-findings.md).

### 10.2. ИИ-пайплайн (RF-стек)
- **STT:** Yandex SpeechKit (primary, стриминг ru; протокол — WebSocket default, ADR-013), SaluteSpeech (fallback), Vosk/whisper.cpp (офлайн/free-тир).
- **LLM-структурирование:** **GigaChat-2 Lite — дефолт** за сменным адаптером backend-прокси (смена провайдера — конфиг backend, не релиз клиента); бенчмарк vs YandexGPT — evidence внутри F2 (Q1 закрыт, ADR-013).
- **TTS:** Yandex/SaluteSpeech — с V1.
- **Хранение:** RF-облако — **Yandex Cloud** (регион `ru-central1`, ADR-013: ко-локация со SpeechKit, managed Postgres+pgvector) — ФЗ-242. Сравнение/цены: [android-ru-tech](research/android-ru-tech.md).

### 10.3. Совместимость наушников
TWS с кнопкой / накладные BT — полная поддержка media-hook; тач-панель без кнопки — активация через tile/BT-autostart; AirPods на Android — только play/pause. Кастомные жесты вендорских наушников до приложения не доходят.

### 10.4. Рекомендуемый стек
- **Android:** Kotlin + Jetpack Compose + Gradle; фоновые сервисы, CoreBluetooth-аналоги (BluetoothHeadset/CDM), MediaSession.
- **Backend:** Python 3.12 + **FastAPI-монолит** (proxy к STT/LLM с ключами, RuStore-биллинг, sync), PostgreSQL (+pgvector для поиска), Redis, объектное хранилище — всё в **Yandex Cloud**; деплой Docker → Serverless Containers (ADR-013). Канонические API-контракты — `specs/_contracts/` (`openapi.yaml`, `thought.schema.json`).
- **Идентичность (ADR-012):** MVP-0 — анонимный **device-token** (ноль трения, без регистрации); MVP-1 — опциональная привязка **VK ID / Яндекс ID** (мультидевайс-sync, обязательна для покупки подписки).
- **Платежи:** RuStore Pay SDK + CloudPayments/YooKassa (СБП-рекуррент, 54-ФЗ).
- **Дистрибуция:** RuStore (primary) + прямой APK + (опц.) AppGallery (free-only).

### 10.5. Платёжный слой в РФ
RuStore Pay SDK (комиссия 15%) для in-store + **внешний биллинг под 0%** через свой эквайер для web/кросс-канала. Старый BillingClient выключается 01.08.2026 → сразу на Pay SDK. iOS-каналы — [ios-billing-options](research/ios-billing-options.md).

## 11. Операционная модель агентной разработки
Полностью — в [agentic-build-operating-model](research/agentic-build-operating-model.md). Кратко:
- **SDD-харнесс** (oriion-совместимый): `.planning/PROJECT.md` + `roadmap/` (волны) + `decisions/` (ADR) + `specs/<фича>/` (EARS) + `.claude/agents/` (сабагенты).
- **Цикл на тикет:** spec → агент кодит → CI-гейты (lint/typecheck/unit/инструментальные на Gradle Managed Devices + Firebase Test Lab) → at нативных кейсах **agent-device CLI** → PR → ревью фаундера на фазовом гейте.
- **Фаундер руками:** одобрение спек/ADR, ревью PR, device-sanity на 2–3 OEM, разовый ops-setup (RuStore/ключи/подпись), клапан эскалации.
- **Публикация:** fastlane + `rustore-publish-gradle-plugin` из CI.

## 12. Монетизация

| Тариф | Цена | Включает |
|---|---|---|
| **Free** | 0 ₽ (без карты) | «Поймай мысль» с лимитом **~30 мин облачного STT/мес**; после исчерпания on-device черновой STT (F6) продолжает работать; история 30 дней, базовый экспорт |
| **Standard** | **~399 ₽/мес** | «Поймай мысль» + встречи/лекции **по квоте ~4 ч/мес облачного STT + on-device микс** (короткие/черновые капчеры — on-device) + все экспорты (Obsidian/Notion/календарь) |
| **Pro** | **~699 ₽/мес** | Квота **~8–10 ч/мес** (уточняется по Q2) + длинная история + (V1) выбор ИИ/intl + приоритет. Не «безлимит» — fair-use/овередж |
| **Годовой** | по ценовой политике (≈ −20–30%) | Ответ на «Дропс за один платёж» |
| **Enterprise** | по запросу (V2+) | Корп-протоколы, SSO, SLA, аналитика, CRM |

**Принципы:** квоты, а не «безлимит» (себестоимость STT ≈ 39 ₽/час, all-in 45–60 ₽/час → break-even Standard ~5–7 ч; квота ~4 ч облачного STT + on-device микс держит маржу >50% — гейт MVP-1); on-device STT удешевляет free-тир; биллинг включается с MVP-1. Числа квот ратифицированы grill-интервью 2026-07-07 (§2.1–2.2).

## 13. Метрики успеха

**North Star:** число пойманных мыслей, **дошедших до действия/destination**, в неделю (на MVP-1 — часов встреч расшифровано/нед).

| Уровень | Метрика | Реалистичный ориентир |
|---|---|---|
| MVP-0 (free) | Activation (D1 завершил первый capture→destination), W1/W4 retention, captures/user/нед, share-rate | activation >40%, W4 retention >25% |
| MVP-1 (монетизация) | Free→Paid 3–6%, trial→paid, retention платящих, MRR, **gross margin на платящего** | маржа >50% после AI-стоимости |
| Операционные | время «реплика→готовая заметка» (неск. сек), **WER на ru-шуме <15%**, crash-free >99,5%, надёжность фон-захвата по OEM, **AI-cost на активного** | — |

**Go/No-Go гейты вместо годовых vanity-цифр:** напр. «переходим к монетизации MVP-1, только если на MVP-0 W4-retention > X и activation > Y». Большие амбиции-цифры на старте не ставим — делаем и оцениваем реальное.
