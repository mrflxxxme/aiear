# EarAI — Технические сценарии (сводка ресёрча, 2026)

> Источник: 4 фоновых ресёрч-агента (iOS, Android-активация, RF-дистрибуция/платежи, RU-пайплайн).
> Статус: рабочая сводка для финального PRD. ⚠️ = требует подтверждения перед разработкой.

---

## 1. iOS — активация и фон

**Главный вывод:** программного «закрытое+заблокированное приложение → мгновенный триггер» для стороннего приложения на iOS **не существует**. Этот слой Apple резервирует за Siri/системой.

**Рекомендованный стек активации (primary → fallback):**
1. **«Привет, Siri → App Intent»** — запускает фоновую сессию EarAI **с заблокированного экрана, не открывая приложение**. Ключевое отличие: App Intent с `openAppWhenRun` форсирует разблокировку; App Intent, стартующий фоновую сессию, — нет.
2. **AirPods stem-press recording (iOS 26)** — нативный жест записи на AirPods.
3. **Control Center / Lock Screen `ControlWidget`** — тап в один клик.
4. **BT-connect Personal Automation** — автозапуск по подключению наушников.
5. **Apple Watch / Action Button (iPhone 15 Pro+/16)**.

**iOS 26 — что использовать:**
- `SpeechAnalyzer` / `SpeechTranscriber` — on-device STT, ~2× быстрее Whisper Turbo.
- `bluetoothHighQualityRecording` — качественная запись с BT-микрофона.
- `BGContinuedProcessingTask` — офлоад обработки чанков.

**Избегать (риск отклонения App Store):**
- 🔴 Silent-audio «Now Playing» хак (перехват медиаплеера тихим треком) → отклонение по 2.5.4.
- 🔴 CallKit/VoIP-обход → iOS 26 убивает не-звонковые приложения, берущие VoIP-пуши.
- 🔴 CoreBluetooth не читает AVRCP/кнопки произвольных наушников.

## 2. Android — активация и фон

**Главный вывод:** надёжной brand-agnostic «волшебной кнопки» при закрытом приложении нет. Самые мощные поверхности (assist-gesture, always-on hotword на DSP, фоновый микрофон) система резервирует за **default-ассистентом (`ROLE_ASSISTANT` + `VoiceInteractionService`)**.

**Рекомендованный стек (primary → fallback):**
1. **PRIMARY (где пользователь согласился): стать default-ассистентом.** `RoleManager.createRequestRoleIntent(ROLE_ASSISTANT)` + реализация `VoiceInteractionService`. Единственный санкционированный путь к: (а) запуску по assist-жесту/кнопке, (б) фоновому микрофону (FGS-исключение), (в) DSP-hotword. ⚠️ Роль может **молча сбрасываться при переустановке** — детектить на каждом старте и переспрашивать. На Samsung боковая кнопка — отдельная настройка.
2. **PRIMARY-триггер захвата встреч: BT-connect + `CompanionDeviceManager`.** `REQUEST_COMPANION_START_FOREGROUND_SERVICES_FROM_BACKGROUND` + слушать `ACTION_ACL_CONNECTED` → легально стартовать mic-FGS из фона. «Надел наушники → EarAI взвёлся».
3. **FALLBACK:** BT-connect → non-mic FGS с уведомлением «тап, чтобы начать запись» (тап = легальный старт mic-FGS). + **Quick Settings tile** (`startActivityAndCollapse`) как ручной лаунчер (0 батареи, 0 риска). + media-button hook (`KEYCODE_HEADSETHOOK`) как in-session-триггер (с дебаунсом; ненадёжно по брендам).

**Жёсткие «нельзя»:**
- 🔴 `BOOT_COMPLETED` → старт mic запрещён с Android 14; Android 15 расширил бан на dataSync/mediaPlayback/camera/phoneCall.
- 🔴 **AccessibilityService для автоматизации (автоотправка сообщений, управление чужими приложениями) на Google Play** — с 28 янв 2026 фактически бан, отклонение почти гарантировано. ⚠️ Возможен **только на RuStore** (политика мягче, но подтвердить у ревью RuStore).
- 🔴 Assist-жест / long-press питания не достанется стороннему приложению без роли ассистента.

**Кнопки наушников по брендам:** портативно ловится только media-button hook (play/pause) и только когда EarAI — активная медиа-сессия. AirPods на Android = только answer/hangup/play-pause. Galaxy Buds/Sony/Jabra кастомные жесты обрабатывает вендорское приложение, до сторонних не доходит. «Кнопка ассистента» на наушниках почти никогда не дойдёт без роли default-ассистента.

## 3. RF — дистрибуция и платежи

- 🟢 **RuStore — основной канал.** Обязательная предустановка на Android (и iOS/Xiaomi с сен 2025), ~67 млн пользователей. Комиссия **15%**. Билить через **Pay SDK** (старый BillingClient умирает **1 авг 2026**). Методы: карты, **СБП (~53% платежей)**, SberPay, T-Pay, carrier billing. Подписки — first-class (trial/grace/hold).
- 🔴 **Два дедлайна 2026:** с **1 фев 2026** билинг RuStore только для **ИП/ООО** (самозанятые не могут монетизировать); BillingClient выключается **1 авг 2026**. → **EarAI обязан зарегистрировать ИП/ООО.**
- 🔴 **Google Play = только бесплатный охват.** РФ-разработчики не получают платежи (с 26 дек 2024), РФ-пользователи не платят. Монетизация — через web-привязку аккаунта, не in-app.
- 🟢 **Ключевой рычаг:** RuStore **разрешает внешний биллинг под 0% комиссии.** → дуальный биллинг: RuStore Pay SDK в сторе + **свой эквайер (CloudPayments или YooKassa)** с рекуррентом по СБП и чеками 54-ФЗ для web/кросс-канала. ИП обязан выдавать чеки 54-ФЗ.
- ⚠️ Huawei AppGallery — рассматривать только как бесплатную дистрибуцию (выплаты РФ-юрлицам в 2026 не подтверждены).

## 4. RU-пайплайн (STT / LLM / TTS)

> Детальная сравнительная таблица — в `research/android-ru-tech.md` (агент дописывает). Сюда внесём после готовности.

Опорные кандидаты для `ru`:
- **STT:** Yandex SpeechKit, SaluteSpeech (Sber/GigaChat), Whisper large-v3 (через юрлицо/прокси), Vosk/whisper.cpp (офлайн).
- **LLM:** GigaChat, YandexGPT/Alisa — доступны и оплачиваемы из РФ; Claude/GPT — только через зарубежное юрлицо/прокси.
- **TTS:** SaluteSpeech, Yandex TTS, ElevenLabs (премиум).

## Что это меняет в стратегии
1. **Android-first подтверждён жёстко** — единственный путь и к hands-free-«магии» (роль ассистента), и к фоновому захвату (CDM), и к приёму денег (RuStore).
2. **Hands-free на Android = «стать default-ассистентом»**, а не «ловить кнопку наушников».
3. **Hands-free на iOS = «Привет, Siri → App Intent»**, а не кнопка гарнитуры.
4. **Юрлицо ИП/ООО — обязательное и срочное** (дедлайн RuStore 1 фев 2026 уже прошёл; для монетизации нужно юрлицо).
5. **Голосовое управление чужими приложениями (W1-витрина)** на Play мертво → только RuStore, и то под вопросом.
